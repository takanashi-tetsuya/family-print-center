# 驗證紀錄

**本專案主要由 AI 製作，經人工核驗。** AI 執行程式修改、部署與自動化測試；使用者負責紙面輸出確認。下文分別記錄自動化驗證與人工實機核驗結果，未測項目不列為通過。

可公開的驗證範圍如下；精確設備位址、UUID、私有字體及家庭測試文件不隨來源發布。

## 2026-10-09 部署驗證

在 OpenWrt 25.12.5、x86_64、Intel N100、8 GB RAM 的 Docker 主機完成部署。容器健康，Writer、Calc、Impress 啟動預覽成功，驗證結束沒有待印任務。

- 當日部署版本 Python **577 項通過**：沙箱內 575 項，另兩項需本機 socket 的測試在允許連線環境通過。
- 公開來源整理後，在不含本機字體快取及家庭資料的來源副本中，Python **651 項通過**，含本機 socket 測試；兩組 JavaScript 測試亦通過。新增紙張遷移、原始碼連結、字體授權保留、發布包邊界及離線部署測試。先前本機的 655 項包含另存的 5 項用紙預算測試，公開套件不包含這些部署紀錄。這些新增修改尚未更新已部署映像，沒有追加實體打印。
- 本地字體包完整同步，展開後 **180 個字體檔**核對 SHA-256、可讀性及字體解析。包含私有導入字體，公開來源本身不附帶這 180 檔。
- 14 份 PDF／DOCX／PPTX／XLSX，加 EPUB、UTF-8 純文字、PNG 各一份，合計 **17 份文件、21 頁預覽**成功；核對多語字、表格、尺寸、方向及裁切。
- 真實瀏覽器核對多文件、預覽、進階取消／套用、模式切換、DPI 和 Cookie 恢復；各台偏好獨立，測試後恢復自動。
- 缺少 CSRF 及跨站來源請求拒絕，未因此送印。

## 2026-10-09 運行與上傳修復

運行數小時後，原生 pycups 2.0.4 的 PPD 批次讀取累積了未釋放的檔案描述符，使網頁卡在搜尋打印機。已部署 PPD 子程序隔離修正，同時修正小 PDF 因 multipart 讀取邊界被誤判超過 100 MB 的問題，處理方法見[教程](troubleshooting.md)。

- 合併修正後 Python **667 項通過**，兩組 JavaScript 測試通過。新增原生 PPD 描述符、真實選項衝突、子程序失敗及有效 PDF 跨讀取邊界測試。
- 原生 PPD 測試連續執行 60 次能力解析及 60 次選項驗證，父程序描述符沒有增加；已下載但無法解析的 PPD、逾時或子程序失敗均拒絕送印。
- 部署服務連續查詢 60 次打印機，網頁程序描述符保持 **9 → 9**，沒有未釋放的 PPD 暫存檔；Brother 驅動／IPP 與 Epson IPP 各完成 10 次 A4 長邊雙面選項驗證，沒有提交工作。
- 自製有效 PDF **2,200,000 bytes** 及 **6,600,000 bytes**，刻意令換行跨越 64 KiB 邊界；兩份均上傳成功、PDF／PNG 預覽成功，測試上傳已清除。真正超大檔案、表單欄位過大及過多欄位仍被拒絕。
- 修正映像繼承已部署字體，全部 **180 個字體檔**雜湊一致且應用帳號可讀。容器健康，Writer、Calc、Impress 啟動預覽成功，瀏覽器顯示兩台打印機、能力及已連線狀態。

這次只部署 `cups_client.py`、`ppd_worker.py`、`config.py`、`app.py` 的修正，其他公開整理項目仍以上節說明為準；保留既有資料卷，沒有追加實體打印。短期連續測試不等同於多日長時間測試，後續仍應留意容器健康及描述符使用量。

## 2026-10-09 預覽與頁面設定

按使用者要求，本次完成程式及本機驗證，暫不更新軟路由。沒有提交實體打印，也沒有消耗用紙預算。

- Python **711 項通過**，五組 JavaScript 測試通過。新增文件切換、手動跳頁、頁碼記憶、舊圖片回應隔離、紙型分組與毫米尺寸、頁邊距及 Cookie／打印方式隔離測試。
- PDF 在指定紙張的四邊頁邊距內等比例排版，保持向量文字、表單可見內容、空白頁及頁碼範圍；原檔不變，暫存檔清除。
- 真正 LibreOffice 的 Writer／Calc 在只輸出驗證 PDF、不送印的測試中，左邊距由 20 改為 40 mm、上邊距增加 10 mm 後，首段文字位置對應移動；DOCX／XLSX 原檔 SHA-256 保持不變。正式打印仍使用原始 Office 文件。
- 用紙自動時，Office 保留原始頁面尺寸；無預覽 PDF 的原稿仍可直接打印。PowerPoint 的自訂頁邊距在提交前拒絕，避免假裝已套用。
- 大 PDF 準備不鎖住其他文件操作；正在準備的文件不能刪除、清理或重複提交。準備失敗可修正重試，提交結果不明仍禁止相同請求重送。
- 本機 18080 真實瀏覽器核對兩份 PDF 切換、手動第 3 頁、返回文件保留頁碼、紙張寬高、四邊輸入及重新載入恢復 Cookie；手機布局沒有橫向溢出，未記錄瀏覽器錯誤。驗證後設定恢復自動，暫時測試服務關閉。

預覽仍是文件原版面，頁面示意圖不代替實際重新分頁預覽；本次未重新人工核驗紙面頁邊距。PowerPoint 的替代操作見[教程](troubleshooting.md#紙張頁邊距與預覽頁碼)。

- 更新映像保留全部 **180 個字體檔**，逐一核對 SHA-256 及應用帳號可讀性。三份 PPD 雜湊及部署前後的完整 CUPS 任務清單相同。

- 在部署映像以應用帳號執行隔離功能測試，核對 PDF 的四邊向量座標、A4 橫向、Letter、份數、頁碼範圍、去重及無效設定拒絕。實際 LibreOffice 只輸出驗證預覽，Writer／Calc 的文字位置符合邊距改動，原檔雜湊不變；沒有向真實 CUPS 提交打印。
- Brother 驅動、Brother IPP、Epson IPP 各完成五次 A4 長邊雙面選項驗證；能力查詢沒有累積檔案描述符。首頁與 **18 個靜態資源**均 HTTP 200，內容雜湊與來源相同。

## 範圍限制

已測文件通過不代表每種格式、Office 版面或選項組合都正確。USB、專用廠商驅動、其他紙匣／紙型、自訂尺寸、全部 DPI／品質和 Epson 每張兩頁未逐項實印。

IPP 宣告、CUPS 完成和預覽只證明相應環節；張數、內容、雙面和方向須人工確認。本次 Epson 工作計數曾與實際紙數不同，合計以人工確認為準。

完整雜湊、預覽、私有備份及逐次紀錄由部署者本機保存，不納入公開 GitHub。重新測試使用自製無敏感內容文件，先設定用紙預算，等待上一工作終止，避免不明狀態重複送印。
